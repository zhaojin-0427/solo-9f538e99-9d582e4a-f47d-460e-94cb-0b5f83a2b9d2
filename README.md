# 变异注释归一化平台

面向变异注释数据员的网页工具：把同一变异的不同插缺写法归一到标准 VCF 表示，
按"单条变异作用后的完整序列"判定等价并合并，避免下游重复注释。

## 功能

- 上传**单条染色体 FASTA**（≤ 4096 碱基）与**变异 CSV**（≤ 20 行，表头含
  `ID,POS,REF,ALT`，POS 从 1 起）。
- 仅接受：**单碱基替换**、**带锚定碱基的纯插入/纯缺失**（VCF 惯例，锚定碱基在事件左侧）。
- 逐行核对 REF 与参考序列；任一非法行 → **整批失败**，不留半份报告。
- 插缺**左对齐**到最左可表示位置（含串联重复中的旋转归一），输出标准 VCF。
- 以"单条变异作用后的完整序列相同"判定等价，**等价行合并**并列出全部源 ID。
- 两份输入可分别**整份更正**；每份报告固定所用输入版本与结果。
- **计算期间更正仍可提交**；旧报告可查但不再是当前结论；迟到完成的结果
  **不能覆盖**更新版本的结论；报告与任务状态单事务写入，失败不留半份。
- **报告写入故障自动恢复**：瞬时写失败（如数据库短暂锁定）自动退避重试；
  连续失败达上限后页面明确显示失败并可**一键重试当前版本**；进程重启后
  被中断的任务自动重新排队。

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:5000
```

数据持久化在命名卷 `appdata`（容器内 `/data/app.db`）。

### 本地运行

```bash
pip install -r requirements.txt
python run.py          # http://localhost:5000
```

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `APP_DATABASE` | `instance/app.db`（容器内 `/data/app.db`） | SQLite 路径 |
| `COMPUTE_DELAY_SECONDS` | `2` | 模拟耗时计算的秒数；此期间可提交更正，用于演示/验证并发语义 |
| `JOB_MAX_WRITE_ATTEMPTS` | `3` | 报告写入连续失败上限，达到后任务标记失败并允许页面重试 |
| `JOB_RETRY_BACKOFF_SECONDS` | `1` | 写失败重试退避基数（第 n 次失败后延迟 base×2ⁿ⁻¹ 秒） |
| `JOB_STALE_SECONDS` | `900` | running 超过该时长视为被中断，由 worker 回收重排（重启恢复的兜底） |
| `WORKER_INJECT_WRITE_FAILURES` | `0` | 演练用：前 N 次报告写入必失败（模拟瞬时写故障），默认关闭 |
| `SECRET_KEY` | 开发默认值 | 生产部署请覆盖 |
| `PORT` | `5000` | 监听端口 |

## 输入格式

**FASTA**：单个 `>` 标题行 + 序列（可换行，仅 A/C/G/T/N，≤4096 碱基）。

**CSV**：表头含 `ID,POS,REF,ALT`（大小写不敏感、顺序不限），数据 ≤20 行。
ID 唯一且不含空白/逗号/分号；POS 为 ≥1 整数；REF/ALT 仅 A/C/G/T/N。

```
ID,POS,REF,ALT
ins_a,2,T,TT        # 插入：锚定 T 之后插 T
del_x,2,TT,T        # 缺失：删锚定后一个 T
snv_1,6,C,A         # 单碱基替换
```

## 归一化与等价规则

- **左对齐**：插入序列 `S` 在锚定 `p` 处，若 `S[-1] == ref[p]`，则整体左移一位并
  旋转（`S' = ref[p] + S[:-1]`），直至最左可表示位置；缺失同理。
- **等价**：两条变异分别作用于参考序列后得到的**完整序列**相同即等价；
  等价行合并为一组，输出该组左对齐后的标准 VCF 行，`ID` 字段列出全部源 ID
  （`;` 分隔）。

## 版本、并发与故障恢复语义

- FASTA / CSV 各自整份版本化（v1, v2, …）；每次更正自动按最新版本组合排队重算，
  同一版本组合的未完成任务在数据库层唯一（部分唯一索引），并发提交不重复排队。
- 报告绑定固定的 `(fasta_version, csv_version)`；"当前结论"由版本匹配派生，
  因此迟到完成的旧版本任务**无法**覆盖新结论，只在历史中标记"已过期"。
- 报告 INSERT 与任务状态 UPDATE 同事务提交；非法输入产生的是一份**完整的
  失败报告**（含错误原因、无任何变异行），不存在半份报告。
- **同一任务至多一份报告**：`reports.job_id` 唯一；重复领取/重复执行撞唯一
  约束时幂等收场，不产生第二份。
- **瞬时写失败自动重试**：报告写入失败（如 `database is locked`）时任务回到
  排队状态并按指数退避重试（`JOB_RETRY_BACKOFF_SECONDS`），写入恢复后自动完成，
  不再永远停在"计算中"。
- 连续写失败达到 `JOB_MAX_WRITE_ATTEMPTS` 后任务标记失败，批次页明确显示
  "报告写入异常"并提供**重试当前版本**按钮（按最新版本组合重新排队）。
- 非法输入是确定性失败，直接形成失败报告，**不**进入写失败重试循环。
- 进程重启时被中断的 `running` 任务自动重新排队（`attempts` 计数保留，崩溃
  循环的任务最终也会到达上限）；worker 异常崩溃的兜底：running 超过
  `JOB_STALE_SECONDS` 由认领方回收重排。

### 故障演练

```bash
# 前 3 次报告写入必失败（= 默认上限），可观察：自动退避重试 → 任务失败 →
# 页面显示"报告写入异常" → 点击"重试当前版本" → 恢复成功
WORKER_INJECT_WRITE_FAILURES=3 docker compose up --build
# 或本地：WORKER_INJECT_WRITE_FAILURES=2 python run.py（观察自动恢复）
```

## 测试

```bash
python -m pytest tests/ -q
```

覆盖：左对齐（同聚物/串联重复旋转）、等价归并、逐行 REF 校验、整批失败、
版本更正、迟到结果不覆盖、失败原子性、真实 worker 线程下的计算期间更正；
故障恢复：瞬时写失败自动重试、达上限后页面失败态与手动重试、失败报告写入
同样重试、重复领取幂等（同一任务一份报告）、进程重启/超时 running 回收、
退避延迟领取、并发排队去重。

## 项目结构

```
app/
  __init__.py    应用工厂（配置 + 后台 worker 线程）
  normalize.py   纯函数核心：解析/校验/左对齐/等价归并/VCF
  db.py          SQLite（WAL）连接、建表与轻量迁移
  worker.py      任务认领、计算、单事务报告写入、写失败退避重试
  views.py       路由：建批、更正、写失败重试、批次/报告页、VCF 下载
  templates/     页面模板
run.py           入口
tests/           pytest 测试
```
